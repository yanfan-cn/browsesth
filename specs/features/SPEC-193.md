## 2. 开工前需求确认

- 已调查事实：
  1. **详情退出冻结的机制**：退出转场开始时 NavDisplay 要把底下的主壳场景整棵重组；主壳 pager `beyondViewportPageCount=4` 使所有标签页（NTP 重页+阅读列表+我的）同时重建 ≈1 秒 → 300ms 转场在重组完成前一帧都出不来 → 冻结 1 秒 → 动画已超时 → 闪切。与阅读器闪切同根；阅读器 Activity 化已被真机确认有效。
  2. 原版 legado 的 MainScreen 同样用 `beyondViewportPageCount=4`，但它流畅——因为其热邻居是便宜书架页；我们的热邻居含 NTP 重页，其异步图片/重组在滑动与转场期间抢占主线程。
  3. `BookshelfScreen`/`AppScaffold`/`BookShelfItem` 与原版逐字节相同或仅 +9 行——阅读列表滚动掉帧不在书架代码本身，在环境（热邻居重组抢占）。
  4. `BookInfoActivity` 已在仓库（fork 自带、完整接线、manifest 已注册 singleTop）：宿主 BookInfoRouteScreen，跨族跳转全走 `MainActivity.createXxxIntent` 模式。
- 疑问处理：已向操作者确认——①详情搬 Activity、**封面 morph（飞入/飞回）彻底放弃**（推翻此前"详情留 Main 保 morph"的决定，流畅度优先；原版本无 morph）；②热邻居 4→0（代价：切标签时目标页现组合）。
- 操作者确认：2026-10-28 两项均选确认。

### 红色问题判定

- 否：不改功能与入口；封面 morph 取消为操作者明示决定（SPEC-189 §6 的 morph 条款全面废止）。

## 3. 为什么做

详情退出冻结与阅读列表滚动掉帧是同一结构性问题的两个面：主壳（含重页热邻居）在错误时机被整棵重组。原版架构的答案是 Activity 边界 + 便宜的单页组合。1.8.4（阅读器）、1.8.5（设置）已两次验证该方向有效，本轮把它补完到详情，并把热邻居成本砍掉。

## 4. 本次范围

要实现：

1. **详情搬入 `BookInfoActivity`**：`MainIntent.createBookInfoIntent` 改指 BookInfoActivity；全部入站跳转（书架卡/主页模块/搜索/探索/AI 聊天/书架分组管理/阅读记录/详情互跳）改 `startActivity`；删除 `MainRouteBookInfo` 路由、Main 导航 entry、MainNavigator 分支与 start-route 映射。
2. **热邻居归零**：主 pager `beyondViewportPageCount` 4→0——滑动/转场期间只有当前页在组合。
3. 进/出详情 = 系统窗口转场，主壳全程存活。

明确不做：

- 不动 `bookCoverSharedElementKey` 源侧引用（单持有者无动画、零风险，留给后续清理）。
- 不动阅读器/设置（190/192 成果）；不做 Perfetto 打点（若滚动仍掉帧，下一轮先打点定位再改）。

## 5. 用户如何使用

1. 点书架/主页卡封面 → 系统窗口转场进入详情；返回 → 系统转场回原页，原页原样在底，无冻结无闪切。
2. 滑动阅读列表：热邻居不再抢占滚动帧。
3. 封面不再有飞入/飞出 morph（已确认放弃）。

## 6. 产品规则

- 详情 = 独立 Activity（原版架构）；主壳不得因详情进出而重建。
- 封面 morph 条款（SPEC-189 §6）废止：详情与阅读器均不再做封面共享元素转场。

## 7. 重要状态与边界

| 情况 | 用户应该看到什么 | 数据/状态处理 |
| --- | --- | --- |
| 卡片→详情→返回 | 系统转场往返，主壳连续 | 详情 Activity 自管 |
| 详情→阅读器→返回 | 系统转场（190 模式） | 阅读器 Activity 自管 |
| 详情内跨族（搜索/角色/书源） | 经 MainIntent 工厂（BookInfoActivity 现成接线） | 不变 |
| 切换主标签 | 目标页现组合（可能稍慢） | 换取滑动与转场流畅 |
