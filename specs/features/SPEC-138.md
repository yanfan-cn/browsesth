## 1. 问题陈述（操作者 2026-10-19 确认继续 SPEC-124 遗留返工）

从网页会话按返回 / `clearActiveToNtp` 退回主页：会话向右滑出的 240ms 期间**整页白屏**（容器底色），滑出结束后 NTP 才瞬间出现——观感是「闪一下白才回主页」。根因是 SPEC-124 B2b 第一版（`BrowserNtpSessionSwitch` pop 分支等 `isIdle` 后才组合 NTP）刻意把 NTP 组合推迟到动画后，滑出期间无处可看。

## 2. 方案选择（操作者 2026-10-19 选定）

**NTP 常驻组合垫底**：会话在场期间 NTP 不再在滑入完成后销毁，而是保持组合于会话层之下；退出滑出时直接露出已就绪的 NTP，无任何白屏、动画期间零 NTP 组合成本。

- 已否决方案：错峰 2~3 帧组合（中段仍可能掉帧）；滑出垫静态快照（需维护快照层）。
- 附带收益：消除 LOG-124 记录的「每次退出重组合 NTP → JIT 反复重编 `BrowserNtpScreen$lambda$96$0`（16MB 编译分配）」。

## 3. 产品规则

- 会话退出滑出期间，用户看到的必须始终是 NTP 内容（或其过渡前的画面），**不得露出容器底色/白屏**。
- 进入会话的过渡维持现状：NTP 垫底 + 会话 240ms 滑入（SPEC-100/101 slide-only）。
- NTP 常驻垫底后，其在会话覆盖期间**不得产生可见行为**：不自动刷新资讯、不抢焦点、不响应触摸（会话满屏在上，天然不透传）。
- 若常驻垫底引起网页浏览期可感知掉帧（NTP 被遮仍参与绘制），允许加「被遮时跳过绘制」的最小优化，不得引入 fade/scale（液态玻璃安全红线）。

## 4. 范围与非目标

- 范围：`BrowserHomeTabScreen.kt` 的 `BrowserNtpSessionSwitch`（手机与平板共用，一处修复双端生效）；必要时 NTP 侧最小配合。
- 非目标：不改 240ms slide-only 过渡定义；不改 `clearActiveToNtp` / park / `exitFinished`（SPEC-100/120）语义；不做预测性返回；不动液态玻璃策略。

## 5. 验收标准（AC）

- **AC-01**：手机（vivo Android 14）从网页会话返回主页：滑出全程可见 NTP（无白屏、无容器底色帧），过渡 ≤ 240ms 不被巨帧吃掉。
- **AC-02**：从历史/书签/标签页打开网页：进入过渡不回退（不闪 NTP，SPEC-124 B2a 保持）。
- **AC-03**：会话浏览期间滑动/滚动无可感知新增掉帧（NTP 垫底不拖累网页帧率）。
- **AC-04**：回归：切标签不重载（SPEC-120）、`showHome` 保留网址/标题（SPEC-094）、网页→NTP 会话释放时机（SPEC-100）、液态玻璃与填充两种表面均正常。
- **AC-05**：平板抽验 AC-01/02。

## 6. 产品硬边界核对

- 浏览器与阅读/漫画同等重要：仅动主页↔会话切换时序，不触阅读视图与抽图。
- 内核不变；无红色问题。
