## 3. 为什么做

步进滚动使进阅读很慢。A 适配因 URL 匹配/`getComicId` 失败静默走启发式，用户感知「完全无效」。集合 B 覆盖更多仍有 JSON 规则的站。小说正文混入站内导航文案；底部状态 Snack 与悬浮底栏重叠。

## 4. 本次范围

要实现：

1. **取消步进加载**：漫画/小说进阅读不再 WebView 多轮滚动等待；以当前页分析/HTTP/适配器为主路径提速。
2. **修复 Cimoc A 匹配与失败可见性**：host/`cid` 宽松匹配；适配失败明确提示并可降级，禁止「静默像旧启发式」。
3. **集合 B**：加载 `sourceBaseUrl.json`（内置 + 可远程刷新）；对含 `parseChapterList*` / `parseImageList` 等字段的源走 JSON 规则引擎；仅 `baseUrl` 的项用于覆盖已知 A 源域名。
4. **小说去噪**：过滤常见网站 UI 控件短句，避免进入正文。
5. **居中状态提示**：阅读流程状态（分析中/加载中/失败）居中 M3 Expressive 展示。

明确不做：

- 图源商店 / 搜源主入口。
- 小说硬编码站 Parser / Legado 书源主路径。
- 保证全网任意站 100% 目录与续载。
- 修改 `specs/CONSTITUTION.md`。

## 5. 用户如何使用

1. 用户打开漫画或小说页，点阅读入口。
2. 屏幕中央出现简短状态（如「正在分析页面…」），不贴底栏。
3. 尽快进入阅读器：命中 A/B 则目录与本章图/文可用；未命中则轻量启发式；失败有明确提示。
4. 小说正文中不应再堆叠「首页/目录/上一章」等控件短句。

## 6. 产品规则

- 进阅读不得再执行「步进滚动直至稳定」类等待环（允许单次短 settle，须有上限且默认路径不依赖其完成懒加载）。
- URL 命中 A 或 B 时优先适配器；失败须提示原因或「将使用通用抽取」，不得静默装作已用适配器成功。
- B 命中且规则含章节列表选择器时，临时书章节列表应反映解析结果（≥2 章时上下章可切换）。
- 系统不得新增图源商店主入口。
- 阅读流程状态提示必须屏幕居中，不得与浏览器悬浮底栏重叠。

## 7. 重要状态与边界

| 情况 | 用户应该看到什么 | 数据或状态如何处理 |
| --- | --- | --- |
| A/B 命中成功 | 较快进阅读器，目录可用（多章站） | 临时书 |
| A/B 命中失败 | 明确提示后降级或回退 | 不写坏书架 |
| 未命中 | 轻量启发式进阅读或失败提示 | 同临时书模型 |
| 分析中 | 居中状态文案 | 可随完成消失 |
| 小说去噪后过短 | 提示提取失败或保留最少正文 | 不伪造长文 |
