## 确认

- 红色：否（本轮不接主页资讯默认流）

## 范围

1. 工具箱（手机底栏 + 平板侧栏）新增：
   - **转发网页**：系统分享面板，内容为当前页标题 + 链接。
   - **下载**：网页触发的下载交给系统下载管理器并提示；工具箱可「下载当前页」。
2. 主页搜索框与浏览地址栏：输入时自动匹配本地书签与历史（标题/网址包含）；书签优先于历史；点选直接打开。

## 明确不做（本轮）

- 不改广告拦截/弹窗实现（研究结论见附录 A）。
- 不接入主页新闻信息流（研究结论见附录 B；R1，留待之后决定）。
- 不重开 Eyeo 原生广告引擎；不换搜索引擎；不改阅读模式抽取。

## 验收

- AC-01：工具箱有「转发网页」；点击调起系统分享，含当前标题与链接。
- AC-02：工具箱有「下载」；在有 http(s) 当前页时可将当前网址交给系统下载管理器并有提示。
- AC-03：网页触发下载时，应用能交给系统下载管理器并有提示（非空 `onDownloadStart`）。
- AC-04：主页搜索框输入已有书签标题或网址片段时，列表出现该书签；点选打开对应网址。
- AC-05：浏览地址栏同样具备 AC-04（含历史；书签排在历史前）。
- AC-06：手机与平板工具箱均具备 AC-01/AC-02。

## 附录 A：广告与弹窗增强研究（不实施）

现状：保守 URL 关键词列表 + 点选 CSS 屏蔽 + `onCreateWindow` 拦弹窗；Aloha Eyeo 因闪退风险关闭。

建议后续顺序：
1. 引入 EasyList/国内补充列表精简子集，仍走 `shouldInterceptRequest`。
2. 内置常见弹层/遮罩 CSS（可开关）。
3. 补强中页跳转与 `_blank` 滥用。
4. Eyeo 仅在稳定修复后再评估。
5. 阅读模式去噪与网页拦截互补。

## 附录 B：主页新闻信息流研究（不实施，R1）

不推荐：今日头条/腾讯新闻/网易等广告密、结构乱的平台流。

较合适候选：澎湃（综合时政首选）、BBC 中文、少数派；接入方式宜为「标题列表 → 打开网页 → 阅读模式」，勿嵌 SDK。

之后决定时优先考虑可选资讯区（用户开启、可关），避免默认预置第三方内容踩宪章边界。
