## 2. 开工前需求确认

- 已调查事实：
  1. 转场动画参数已与原版一致（设置 Shared Axis=SPEC-162 逐字照抄；详情 300ms、网页禁 fade 亦然）。剩余差距来自渲染成本而非动画代码。
  2. 液态玻璃逐帧采样是全局最大元凶：约 35 处玻璃；底栏/顶栏玻璃每帧把运动内容重画进离屏层再跑 blur。阅读列表滑动掉帧、液态玻璃模式恶化与之直接吻合。
  3. **填充模式也卡**：填充态玻璃采样已关（AppScaffold 门控、GlassCard 为普通 Surface），填充模式的列表掉帧另有来源——封面图无显式解码尺寸约束（Coil 按约束解析，但列表项在快速滚动时仍反复解码/重组）、M3 顶栏 scrollBehavior 折叠逐帧重组、列表项 lambda 不稳定。
  4. 设置退出「无动画卡顿」：转场在播，但 NavDisplay 场景切换把底页（主壳）拆掉重组，重组帧无内容 → 观感为闪切/无动画。与阅读器闪切同根；阅读器搬 Activity 已被真机确认「改善很多」——设置采用同一解法。
  5. 操作者确认：①接受「运动期间玻璃自动降级为半透明纯色 fallback，静止后无缝切回」；②一次性全做阶段 1-3；③方法论与 1.8.4 相同——照原版 legado 的 Activity 架构（原版 gedoor legado 的设置本就是 Activity）。
- 疑问处理：诊断中已按操作者修正收敛（玻璃≠全部原因）。

### 红色问题判定

- 否：不改产品边界与功能；玻璃运动降级为临时视觉状态（静止即恢复），操作者已确认接受。

## 3. 为什么做

流畅度问题遍布全 app 且与玻璃样式正相关，但填充模式也卡——说明至少三路独立成本：玻璃逐帧采样（液态模式）、设置/全屏页进出时的底页重组（所有模式）、列表项渲染（填充模式）。一次性收敛三条线，方法论沿用已验证成功的「Activity 化 + 原版转场」。

## 4. 本次范围

### A. GlassMotionGate——运动中玻璃自动降级

1. 新建 `ui/theme/GlassMotionGate.kt`：全局可组合状态 `suppressed`；提供 `suppressWhileScrolling`（滚动中置位）与导航转场期置位。
2. 接线点：
   - `ChromeSurfaceStylePolicy.isLiquidGlassActive` 增加全局门（`GlassReadiness.ready && !GlassMotionGate.suppressed`）——单点接线覆盖全部玻璃工厂；真机若发现某处布局依赖该判定产生跳动，再为该处拆非门控变体。
   - 滚动源：阅读列表（书架网格）、NTP 资讯流、书城列表、设置类列表（进 Activity 后为其列表接线）。
   - 导航转场：MainActivity 导航栈变化后约 600ms 内抑制；阅读器/设置 Activity 内部转场同理。
3. 降级视觉 = 既有 fallback（clip + 半透明纯色，alpha 与玻璃态相近——GlassReadiness 同款），静止后无缝切回。

### B. 设置搬独立 SettingsActivity（含全部设置族路由）

1. 新建 `ui/config/SettingsActivity : BaseComposeActivity`：自身 NavDisplay 承载设置族（Settings 根 + SettingsBrowser/BrowserPrivacy/BrowserPickBlock/SettingsOther/Read/Cover/CoverAlbums/Theme/ThemeManage/CustomTheme/Backup/Ai 族/DownloadCache/Translation/Private）；转场沿用 Shared Axis（照抄现 metadata）。
2. 入口统一改 `MainIntent.createSettingsIntent(...)`（start route 参数）：我的→设置、浏览器工具箱→设置、净读⋮→更多设置、私密闸门→私密设置、更新/关于等全部调用点。
3. 设置族内跨出跳转（开阅读器/书源登录/书源编辑/网页/导入等）改走 MainIntent 既有工厂；阅读设置等若需预览回调按最小实现处理。
4. 删除 MainActivity 导航里的设置族路由与 MainNavigator 对应分支（含 SPEC-144/156/162 的设置专用栈逻辑）；保留平板设置布局能力（TabletSettingsScreen 迁入新宿主，双栏布局按自身配置判断）。
5. 退出 = finish()，底页（我的/网页）原样存活，系统窗口转场。

### C. 列表渲染减负（填充模式掉帧）

1. 封面请求显式解码尺寸：书架网格/主页阅读列表卡/NTP 封面行按显示 px 传 `.size()`，避免大图反复全尺寸解码。
2. 顶栏折叠与列表项重组稳定性核查（能以最小改动修的才动，不做大重构）。

### 明确不做

- 不删液态玻璃模式、不改玻璃观感（静止状态）。
- 不做帧耗时打点系统（阶段 4 推迟：需要真机 Perfetto 定位后才有价值，避免盲目优化）。
- 不动浏览器会话页转场、阅读器（190 成果）、详情（191 成果）。

## 5. 用户如何使用

1. 滑动阅读列表/任何列表：玻璃短暂变纯色再切回（液态模式），滑动帧率明显提升；填充模式受益于封面解码与重组优化。
2. 我的→设置→返回：系统窗口转场，我的页原样在底，无闪切。
3. 网页→工具箱→浏览器设置→返回：同上，网页不重建。

## 6. 产品规则

- 玻璃效果静止态观感不变；运动态允许自动降级为 fallback（已确认）。
- 设置功能与入口不变，仅宿主架构变化。
