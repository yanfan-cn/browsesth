## 1. 开工前需求确认

- 已调查事实：回 NTP 后 `showHome`+park 保留 A；`openUrlInActive(B)` 在 park 时不调 `loadUrl`；`LaunchedEffect` 把 `lastUrl=A` 当成「页内超前」拒绝加载 B；`onReady` 重挂也不加载。地址栏现按 SPEC-024 显示搜索词而非页标题。
- Agent 最终复述：①回主页后再搜索/历史/书签打开却回到旧站；②地址栏与缩略图标题常与当前页不符。根因=park 后显式导航未真正 load + 「trust lastUrl」误伤。
- 任务下达者确认：2026-10-15 回复「以上复述准确」；地址栏未编辑时「跟当前页标题/站点名」。
- 红色问题：否（局部导航/展示修正，不改内核与产品边界）。

## 2. 为什么做

日常从主页再开页却回到旧站，标签元数据与真实网页脱节，地址栏也不跟页面，标签页体感混乱。

## 3. 本次范围

要实现：

1. 从 NTP（`showHome`）或 park 状态，经搜索 / 历史 / 收藏书签 / `openUrlInActive` 打开目标 URL 时，**必须加载该 URL**，不得停留在 park 前的旧页。
2. 网页会话中、地址栏**未获焦编辑**时，显示**当前页标题**；标题为空时显示**站点名（host）**。
3. 获焦编辑时便于改址：显示当前页 URL（或可提交的输入）；失焦未提交则恢复为标题/站点名。
4. 标签页缩略图标题跟 `tab.title`（随页标题更新）。

明确不做：

- 不改标签 park/切标签不重载（SPEC-120）。
- 不改「回 NTP 保留 url 以便缩略图点回」（SPEC-094）本身，只修再导航。
- 不改 SPEC-124 过渡动画返工（B2b 白屏另案）。
- 不换内核。

## 4. 产品规则

- 当用户在当前标签处于 NTP/`showHome`，并提交搜索或从历史/书签打开 URL 时，系统必须导航到该目标；内核页与 `tab.url` 一致。
- 当用户从标签网格点回仍有 url 的标签时，仍恢复 park 页、不强制网络重载（与 SPEC-094/120 一致）。
- 当网页已打开且地址栏未编辑时，地址栏显示页标题；无标题则 host；不得长期卡在旧站搜索词（**覆盖 SPEC-024 中「未编辑时显示搜索词」对已打开网页的约定**）。
- 编辑中提交仍按现有解析（URL / 搜索引擎）加载。

## 5. 验收标准

- [ ] **AC-01**：打开 A → 回浏览器主页 → NTP 搜索任意词或打开历史/书签中的 B：画面为 B（或该搜索结果页），不是 A。
- [ ] **AC-02**：同一流程后，地址栏未获焦时显示 B 的页标题（或 host），不是 A 的标题/旧搜索词；标签缩略图标题与 B 一致（或随后到标题回调后一致）。
- [ ] **AC-03**：打开 A → 回主页 → 在标签页点该标签缩略图：仍回到 A 且不整页网络重载（park 恢复；允许短暂占位）。
- [ ] **AC-04**：会话中点链接从 A 到 B：地址栏未获焦时跟 B 标题/站点名；切标签 A↔B 不重载（SPEC-120 回归）。
- [ ] **AC-05**：手机与平板抽验 AC-01/02。
