## 范围

1. 新建统一「存储与缓存」页，入口在浏览器设置内：列出各缓存分类实时大小，支持单项清理与一键清理。分类至少含：封面 HTTP 缓存（`cache/http_cache`）、封面文件缓存（`files/cover_cache`）、漫画缓存（`cache/manga_cache`）、净视/朗读音频缓存（`externalCache/exoplayer`）、浏览器内核缓存（`app_webview`/`app_bromium` 的 HTTP 缓存部分，不含 Cookie/登录态）、其它缓存（cache 目录剩余部分）。
2. 浏览器内核缓存自动控制：设容量上限（默认 200 MB，可调），超限时自动清理内核 HTTP 缓存（保留 Cookie/站点数据）；在无活动网页会话的时机（应用启动早期/浏览器退出后）执行，避免运行中删除导致内核状态异常。
3. 清理逻辑与旧入口复用同一套原语（`BrowserClearDataHelper`、`clearHttpCache` 等），不重复实现；旧入口（设置→下载与缓存、浏览器→清除浏览数据）保持可用。
4. 实施第一步 adb 真机实测各缓存目录大小，确认 800 MB 构成，实测数据记入 Log 并据此校准默认上限。

## 边界

- 不清理用户数据：下载内容、书籍缓存目录（`downloadDir`）、书签/历史/密码、Cookie 与站点设置不在此页清理范围。
- 不引入对内核类的按名反射（release R8 风险，见 workspace 规则）。
- 不自动改旧入口语义（如「清除书籍缓存」整删 cache 目录的现状行为不在本 Spec 修正）。

## 验收

- AC-01：真机浏览器设置内可进入「存储与缓存」，各分类显示实测大小；截图。
- AC-02：单项清理与一键清理后，对应分类大小归零/明显下降，系统设置中应用缓存数值下降；截图。
- AC-03：内核缓存超上限时（可用临时小阈值验证）自动清理生效，Cookie/登录态保留。
- AC-04：分类大小计算与上限判定有单元测试（有效断言）。

## 变更记录

- 2026-11-04（操作者确认）：「存储与缓存」不再作为浏览器设置内的独立页，整页内容并入 **设置 → 下载与缓存**：
  - 统一的六个缓存分类取代原「HTTP缓存」组的封面/漫画两条（口径合一，避免重复条目）；
  - 新增「自动清理」组（开关 + 内核缓存上限）与「一键清理全部缓存」；
  - 操作者选择删除原页面分组：「网络」（阅读侧用户代理 + Cronet 开关失去调整入口）、「高级」（「清理缓存」由统一清理替代；「压缩数据库」失去入口）、「图片缓存」（图片绘制缓存与漫画保留数量为内存设置，失去调整入口，配置值仍生效）；
  - 浏览器设置内「存储与缓存」入口移除，「清除浏览数据」保持不变；
  - 对应路由 `MainRouteBrowserStorageCache` 与独立 `StorageCacheScreen` 移除，`StorageCacheStats`/`StorageCacheAutoTrim`/`StorageCacheViewModel` 保留并被下载与缓存页复用。
