# SPEC-098：资讯启动预加载 + NTP 滚动恢复（对齐网页记位置）

| Spec ID | SPEC-098 |
| 状态 | Done |
| 基线 | SPEC-097 / 13.4 之后 |
| 依据 | 操作者确认：启动预加载资讯；进文章返回恢复滚动（参考网页记位置）；完成后不构建 |

## 用户问题

1. 资讯流开启时，进入主页常仍在加载；希望启动阶段已预拉，进主页时列表可用。
2. 点资讯进文章再回主页，滚动位置多次修仍丢；需对齐网页浏览记位置方式。

## 范围

### 做

- 资讯总开关开启时，App 启动后台按当前源写入 `BrowserNtpNews` 缓存（3h TTL 不变）。
- NTP 滚动：离开记住 offset；恢复前勿被 0 覆盖；内容可测后多次重试 scrollTo（对齐 `BrowserScrollMemory` / `restoreScrollY`）。
- 返回不强制刷新资讯。

### 不做

- 不改资讯源集合、TTL、分页；不构建 APK；无痕不预加载/不展示。

## 产品规则

1. 开启资讯且非无痕：冷启动即后台预加载；主页优先缓存命中。
2. 进文章再回 NTP：滚动位置与离开前一致（可观察）。

## 验收标准

| ID | 前提 | 操作 | 可观察结果 |
| --- | --- | --- | --- |
| AC-01 | 资讯开、有网 | 冷启动进主页 | 资讯较快出现或已有列表，非长期空白 |
| AC-02 | 资讯开、已滚动 | 点文章再回 NTP | 滚动位置与离开前一致 |
| AC-03 | 回 NTP | 观察列表 | 未自动强制整表刷新 |
