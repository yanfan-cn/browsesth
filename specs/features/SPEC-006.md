## 2. 开工前需求确认

- 已调查事实：当前 `AwContentsHostView` 强制 `LAYER_TYPE_SOFTWARE`，且 `DrawFnAccess` 为空实现；系统 WebView 生产路径为硬件 Canvas 上 `drawWebViewFunctor`。软件路径易导致视觉缩放异常与滑动差。底部白条经操作者确认**不是 bug**。
- Agent 复述：修苹果顶栏压扁 + 提升滑动；不把底白当缺陷。
- 任务下达者确认：2026-10-01「底部白条已经不在，是刚好下一个页面是白色的；其他的你继续改。」
- 确认后需求变化：相对 SPEC-005，AC 底白作废；范围收窄为顶栏+滑动。

### 红色问题判定

- 是否涉及：否（渲染路径实现细节，不改内核品牌/产品边界）
- 上级决策包：无

## 3. 为什么做

苹果官网顶栏仍被纵向压扁；滑动仅一般。根因指向强制软件层 + 未接入硬件 DrawFn。

## 4. 本次范围

要实现：

1. 接入与系统 WebView 同类的硬件 `drawWebViewFunctor` 绘制路径。
2. 取消强制 software layer（保留软件表作为系统回退）。
3. 真机：苹果顶栏高度接近正常；滑动明显好于 1.5 软件包。

明确不做：完整移植 Chromium 测试用 HardwareView/ContextManager 双 Surface；底白再修；阅读视图。

## 5. 用户如何使用

打开苹果官网 → 顶栏图标/高度正常 → 上下滑动更顺。

## 6. 产品规则

- 主路径仍 Aloha；不得改回系统 WebView 控件。
- 硬件绘制失败时不得静默白屏当成功（应可回退或有日志）。
- 保留既有滑动手势策略（Pager 不抢手势等）。
