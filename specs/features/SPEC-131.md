## 3. 为什么做

用户在巡页看网页视频时点全屏无反应或无法正确退出，因为内核回调未接到壳层。修好后，常见站点可在浏览器内正常全屏观看，再进入阶段 B 的增强播放器。

## 4. 本次范围

要实现：

- 网页 HTML5 视频进入全屏时，视频铺满当前 Activity 内容区，隐藏浏览器顶/底栏与系统栏（或等价沉浸）。
- 退出全屏（站点控件、系统返回、内核 `onHideCustomView`）后恢复浏览器壳与系统栏，播放进度不因进出全屏而重置。
- 全屏期间系统返回优先退出全屏，不直接关掉标签或退出 App。

明确不做：

- 倍速、字幕、清晰度、后台播、手势调亮度/音量/倍速（→ SPEC-132）
- 画中画（本阶段尽力可为；做不到不阻塞 A 验收，以 132 为准）
- 嗅探流地址与原生 ExoMedia 播放页（→ SPEC-132）

## 5. 用户如何使用

1. 在巡页打开含 HTML5 视频的网页并开始播放。
2. 点击页面或播放器提供的全屏控件。
3. 视频进入全屏沉浸；浏览器地址栏/底栏不可见。
4. 点击退出全屏或按返回 → 回到原网页布局，视频继续（或按站点自身逻辑暂停，但不得白屏/卡死壳层）。

## 6. 产品规则

- 当内核调用显示自定义全屏视图时，系统必须将该视图置于浏览器内容之上并进入全屏 UI 状态。
- 当内核调用隐藏自定义全屏视图，或用户按返回且当前处于全屏时，系统必须移除全屏视图、回调内核、恢复浏览器壳与系统栏。
- 若全屏请求的视图为空或已有全屏进行中，系统必须安全拒绝/结束，不得崩溃。
- 系统不得在全屏进出后丢失当前标签的网页会话（URL/前进后退栈）。

## 7. 重要状态与边界

| 情况 | 用户应该看到什么 | 数据或状态如何处理 |
| --- | --- | --- |
| 正常全屏 | 视频铺满、壳隐藏 | 持有 CustomViewCallback |
| 正常退出 | 浏览器壳恢复 | 回调 onCustomViewHidden、清引用 |
| 返回键 | 先退出全屏 | 消费 Back，不 Pop 路由 |
| 无视频/站点不调全屏 | 无变化 | 不伪造全屏 |
| 切换标签/回 NTP | 不得残留全屏层 | 强制清理全屏状态 |
