## 为什么做

在网易新闻、腾讯新闻正文页选择「图文混合」后，正文里的图片不出现（缺图或占位失败）。纯文本有时仍可读。用户需要正文图留在图文混合结果里。

## 范围

要实现：

- 网易正文图（类名含 `image-lazy`、`image-reload`，地址在 `data-src`，例如 `dingyue.ws.126.net`）进入图文混合正文，成为真实 `<img src="…">`。
- 在腾讯新闻页（`news.qq.com`、`new.qq.com`、`view.inews.qq.com`）手动选「图文混合」时，先等到正文图出现，或正文区域已稳定，再抽取，避免页面还没准备好就抽空。
- 浏览器网页书下载正文图时，仍带 SPEC-092 的 Referer 与手机 UA。章节地址是 http(s) 时，Referer 用该章节地址。

明确不做：

- 不改「文本」去图、「图片」进漫画阅读器。
- 不给非腾讯站点的图文混合额外等待。
- 不新增站点爬虫规则，不整包适配所有门户。
- 本次不组装 APK、不进位版本号。

## 产品规则

- 类名或图片地址里单独出现的 `ad` / `ads` / `advert` 仍视为广告图，不进入正文。
- `reload`、`load`、`upload`、`read` 这类词里碰巧包含的字母 `ad` 不得当成广告。
- 腾讯新闻图文混合：正文区已有可用图片则立即抽取；否则继续等到正文区稳定（至少约 0.7 秒且连续两次探测不变）或约 2.8 秒上限，然后仍抽取文字。
- 等待期间沿用现有「正在提取」遮罩，用户可取消。
- 下载正文图：章节 http(s) 地址优先作为 Referer；没有则用打开该页时记下的页面地址，再没有则用目录地址。非浏览器网页书不附加这组请求头。

## 验收标准

- AC-01：类名为 `image-lazy image-reload`、`data-src` 为 `https://dingyue.ws.126.net/...` 的图片，抽取结果包含对应 `<img src="https://dingyue.ws.126.net/...">`。类名 `ad` / `ads` / `advertisement` 或地址含 `/ads/` 的图片仍被丢掉。
- AC-02：手动「图文混合」且页面主机为 `news.qq.com`、`new.qq.com` 或 `view.inews.qq.com`（及其新闻子域）时，抽取发生在正文图已出现，或正文探测已稳定不少于约 0.7 秒，或达到约 2.8 秒上限之后。其它网站的图文混合不因此等待。文本模式不因此等待。
- AC-03：`origin` 为 `browsesth://web-novel`（或网页漫画书）时，图片请求仍含手机 UA；章节 URL 以 `http` 开头时 Referer 为该章节 URL；否则回退到页面 URL。
- AC-04：真机抽查一页网易新闻、一页腾讯新闻：图文混合正文可见正文图。本仓库环境无设备，真机项在 Log 标为未验证，并写明操作步骤。
