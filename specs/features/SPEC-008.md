## 3. 为什么做

打开网页后外壳与 UI 设计文档不一致：控件散落顶栏、无浏览器底栏、与主页底栏叠层。对齐 §3.2 可降低误触、腾出阅读入口位置，并为后续阅读视图留蓝钮。

## 4. 本次范围

要实现：

1. 顶栏：左侧返回（回 NTP）、中间地址栏、右侧刷新；点选屏蔽/复制链接等次要操作进溢出菜单。
2. 悬浮底栏（无阴影）：后退、前进、工具箱、标签页（占位提示「即将支持」）、右侧独立蓝色圆形「阅读视图」（可见，点击提示未就绪）。
3. 工具箱：添加书签、查看历史（沿用现有列表对话框即可）、广告拦截开关（尽量会话内即时生效）、进入浏览器设置。
4. 有浏览器会话且在 Home 页时：**隐藏**主 App 底栏（Home/书架等），只留浏览器底栏。
5. 新 UI 无阴影；不改内核、NTP、阅读抽正文、多标签引擎。

明确不做：

- §3.3 ReadView 抽正文；正式书签/历史页；多标签；Banner 广告；全库去阴影；Compose 全迁。

## 5. 用户如何使用

1. 在 NTP 打开网址 → 进入会话页。
2. 顶栏可改地址并前往；刷新重载。
3. 底栏后退/前进；工具箱添加书签、看历史、开关广告拦截、进设置。
4. 点标签或阅读视图 → 提示即将支持 / 未就绪。
5. 顶栏返回或系统返回（无网页历史时）→ 回 NTP，主 App 底栏恢复。

## 6. 产品规则

- 有会话时系统必须隐藏主 App 底栏；无会话或离开 Home 时恢复。
- 标签按钮必须可见且提示「即将支持」，不得假装已有多标签。
- 阅读视图蓝钮必须可见；点击不得进入空白页，须明确提示未就绪。
- 广告拦截开关变更后，后续网络请求须按新状态；开启时对当前页尽力执行已有自定义隐藏脚本。
- UI 文案不得出现书源/图源/漫画下载等敏感词。
- 不得在网页内容区注入 App 广告或悬浮控件。

## 7. 重要状态与边界

| 情况 | 用户应该看到什么 | 数据或状态如何处理 |
| --- | --- | --- |
| 正常会话 | 顶栏+网页+浏览器底栏，无主底栏 | sessionUrl 非空 |
| 回 NTP | NTP + 主底栏 | sessionUrl 清空 |
| 标签/阅读占位 | Toast/Snack 提示 | 无状态变化 |
| 广告拦截开→关 | 新请求不再拦；已加载广告不保证消失 | prefs 持久化 |
| WebView 深链路由 | 可用会话壳；设置回调可缺省 | 不影响 Main 底栏逻辑 |
