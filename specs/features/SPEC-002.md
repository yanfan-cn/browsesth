没有选定并通过验证的内嵌内核，阶段 A 的浏览器与后续拦截能力无法可靠交付。必须先用短试验证「许可能用、API 够用」，再锁品牌，避免整仓迁入后才发现引擎不合格。

## 6. 产品规则

- 当完成选型时，系统（文档与依赖）必须指向唯一默认 SDK（名称、获取方式、目标 Chromium 主版本或 release 标签）。
- 当许可 spike 失败（禁止私有发行、附加专有条款不可接受、归属不清）时，不得锁定该候选。
- 当 API spike 无法证明下列能力时，不得锁定该候选：
  1. 加载 HTTPS 页面并执行 JS（或等价）；
  2. **广告资源拦截**：拦截或等价阻断指定 URL/资源请求；
  3. **跳转中页跳过**：可观察并干预导航（如 `shouldOverrideUrlLoading` / 等价）以跳过中间页。
- ABI 仅 arm64-v8a；体积无上限。
- 版本策略 L1：记录如何升级到更新的 Stable 对应发布物。
- 系统不得在无 spike 证据时将候选标为「已选定」。

### spike 定义（本合同用语）

**spike**：在正式大规模产品开发前，用最短时间做的定向技术试探，目的是验证关键假设。本 Spec 的 spike 仅含：

1. **许可 spike**：阅读 LICENSE/NOTICE/发布说明，判断私有仓库与发行是否可行及须遵守的义务（保留声明等）；
2. **API spike**：用文档、AAR/源码检查，并在可行时用最小工程/设备验证上述三类能力；不能运行时必须在 Log 标「未验证」并不得锁定，或改用已运行验证的备选。
