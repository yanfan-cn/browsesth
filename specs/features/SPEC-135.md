## 2. 开工前需求确认

- 已调查事实：`BrowserVideoOfferBus` 全局保留上次 offer，换站不 clear；提示条仅按 dismissedUrl 过滤。
- Agent 最终复述：换站清 offer；迷你胶囊宽约屏宽 75%、底栏上方居中；四键：播放 / 听音频（仅后台音频+通知）/ 画中画（一键进 PiP）/ 关闭。
- 任务下达者确认：2026-10-18 确认三点细则。
- 确认后需求变化：无。

### 红色问题判定

- 否：交互与 offer 生命周期修复，不改变产品边界。

## 3. 为什么做

换站后旧视频提示误导；原提示条能力单一，听音频/PiP 需进全屏再操作。

## 4. 本次范围

1. 主框架开始加载新页时清除视频 offer；提示仅对应当前页有效流。
2. 提示改为底栏上方居中迷你胶囊（宽约屏宽 75%），四键：播放、听音频、画中画、关闭。
3. 听音频：不进全屏播放页，仅后台 ExoPlayer + 媒体通知。
4. 画中画：从胶囊一键进入系统 PiP（可短暂启播放页再进 PiP）。

明确不做：改嗅探规则；改设置开关默认值。

## 5. 用户如何使用

1. A 站出视频胶囊 → 可播/听音频/PiP/关。
2. 打开 B 站（无视频）→ 胶囊消失，不得再播 A 的流。
3. 听音频 → 通知可控暂停/停止，无全屏页。
4. 画中画 → 直接进系统小窗。

## 6. 产品规则

- 主框架 `onMainFrameLoadStarted`（或等价换页）时必须 clear offer。
- 听音频不得启动全屏 `BrowserVideoPlayerActivity` 作为用户可见页。
- 画中画必须进入系统 PiP；API 不足时诚实 Toast，不假装成功。
- 关闭后同一 offer URL 在未再嗅探前不再显示。

## 7. 验收标准

- [ ] AC-01：A 站有提示 → 进 B 站无视频 → 提示消失；不得打开 A 的流。
- [ ] AC-02：胶囊宽约 75% 屏宽、底栏上方居中；含播放/听音频/画中画/关闭。
- [ ] AC-03：听音频无全屏页，有通知可停。
- [ ] AC-04：画中画进入系统 PiP（API≥26）。
- [ ] AC-05：关闭后同 URL 不反复弹出直至新嗅探。

## 8. 对话确认结果

- 2026-10-18：听音频=仅后台+通知；PiP 一键；胶囊居中 75% 宽。
