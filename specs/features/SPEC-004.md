## 3. 为什么做

用户打开 App 仍可能落到非浏览器主壳，且无法屏蔽广告、弹窗与拉起其它 App 的跳转。本轮把首页稳定为浏览器，并提供可验收的首版净化，使日常浏览更干净、更可控。

## 4. 本次范围

要实现：

1. **启动与首页**：点桌面图标进入 App 后，默认落在**浏览器主页**（Aloha）；原 Home 页模块内容本轮不再作为首页内容展示。
2. **底栏**：暂时**保留**底栏（Home / 书架 / RSS / 我的等现有可见项）；Home 对应浏览器主页。
3. **浏览器相关设置**：放在 **「我的」→「设置」** 内（开关/列表入口，可到达即可）。
4. **导航与持久化复验**：合并包路径上 HTTPS、前进/后退/刷新、书签或历史杀进程后仍在（人工验收）。
5. **自动广告屏蔽**：内置规则表；对匹配的广告类网络请求予以拦截（不加载）。
6. **手动屏蔽**：用户在页面上点选元素，按**当前域名**保存自定义屏蔽规则，之后同域再生效。
7. **阻止弹出式窗口**：非用户预期的新窗口/弹窗不打开。
8. **外链一律拦截**：企图打开本机其它应用的链接（如 `intent://`、非 http(s) 自定义 scheme、应用商店类等）一律拦截，并给用户明确提示；本轮不提供「仅本次打开」例外（规则注明后续可改）。

明确不做：

- Compose 整 App / 剩余 View 页迁移；
- 小说阅读视图（Slice V）、漫画抽图；
- 次要系统 WebView 全换 Aloha；
- 在线更新广告规则库、众包规则；
- 跳转中页智能跳过的完整产品化（选型硬条件 API 可复用探针逻辑，但不作为本 Spec 独立 AC，除非实现中顺带可用）；
- 删除底栏或重做「我的」信息架构；
- 改宪章；更换 Chromium SDK 品牌。

## 5. 用户如何使用

1. 用户点桌面图标 → 进入浏览器主页（地址栏/网页区域可见）。
2. 输入或打开 HTTPS 网址 → 页面加载；命中内置广告规则的资源不出现（或明显减少）。
3. 用户开启/使用「手动屏蔽」→ 点选页面元素 → 确认后该元素按当前域名被屏蔽；再进同站仍生效。
4. 页面尝试弹窗或跳转其它 App → 不跳出；用户看到「已拦截」类提示。
5. 用户可在「我的」→「设置」中找到浏览器相关开关或屏蔽管理入口。
6. 用户可前进/后退/刷新；添加书签或产生历史后，杀进程再进仍可见（至少一种）。

## 6. 产品规则

- 冷启动（桌面 LAUNCHER）默认目的地必须是浏览器主页，不得默认停在原 Home 模块内容页。
- 底栏保留；点击 Home 进入浏览器主页。
- 广告自动拦截默认开启（若提供总开关，默认 ON；状态持久化）。
- 手动屏蔽规则按域名存储在本地；删除规则后同域不再应用该条。
- 弹窗：`window.open` / 非手势触发的新窗口不得展示为独立浏览会话（拦截或忽略）。
- 外链：非 `http`/`https`（及浏览器内必要的 `about`/`data` 若出现）意图拉起外部应用时必须拦截并提示；不得静默调用其它 App。
- 不上传用户浏览正文或自定义屏蔽列表到开发者服务器。
- 主浏览路径不得改回系统 `android.webkit.WebView`。

## 7. 重要状态与边界

| 情况 | 用户应该看到什么 | 数据或状态如何处理 |
| --- | --- | --- |
| 正常打开网页 | 浏览器主页加载目标 URL | 历史按现有策略记录 |
| 广告请求被拦 | 对应广告位空白/未加载；整页其余内容可读 | 仅丢弃该请求 |
| 手动屏蔽成功 | 元素消失或不再显示；有确认反馈 | 写入该域名规则 |
| 弹窗被拦 | 无新窗口；可选短提示 | 不新建会话 |
| 外链被拦 | 明确「已阻止打开其它应用」类提示 | 不发起外部 Intent |
| 内置规则未覆盖的广告 | 广告可能仍可见 | 可用手动屏蔽补救 |
| Aloha/加载失败 | 明确错误，可重试 | 不伪造成功 |
