# Agent 开发入口

Agent 每次只沿着当前任务的引用读取必要资料。“任务下达者”指当前聊天中向 Agent 提出任务、回答问题并确认是否开工的人。

## 开始一项新工作

1. 只以 `CONSTITUTION.md` 为正式宪章；其他相似文件即使存在，也只是参考或历史备份。
2. 从 `docs/` 找到本功能的需求依据。
3. 先只读调查；有疑问时用非技术语言集中提问。
4. 疑问全部解决后，在聊天框简洁、明确地完整复述最终需求，等待任务下达者回复“确认”。
5. 确认前不得创建或修改任何项目文件；已有文档不能代替本次确认。
6. 完成六类红色问题检查；红色问题先生成决策包并取得上级批准转述。
7. 收到“确认”后复制 `features/SPEC-TEMPLATE.md`，再进入 Spec → Plan → 实施 → Log → 验证交付。
8. 需求变化时立即暂停，重新复述并再次取得“确认”。

这套流程由 Agent 自动触发。任务下达者只需提出目标、回答必要问题，并在确认 Agent 的最终复述后回复“确认”。在此之前禁止修改任何项目文件。

```text
CONSTITUTION.md
docs/需求材料 → features/SPEC-XXX.md → plans/PLAN-XXX.md → logs/LOG-XXX.md
```

## 三份工作文档各管什么

- Spec：产品合同。说明为什么做、做什么、不做什么、用户看到什么、怎样验收。
- Plan：工程合同。说明现状证据、采用什么方案、改哪里、按什么顺序、怎样测试与回退。
- Log：事实记录。说明实际改了什么、跑了什么、结果如何、哪里偏离、还有什么没验证。

不要把同一段背景复制三遍，用 ID 和相对链接追溯即可。

## 何时必须找上级

产品定位和范围、核心用户行为、核心技术架构、数据安全隐私、外部影响成本、验收承诺属于红色问题，必须找上级。先完成调查并生成决策包；普通局部、可回退事项由当前开发人员确认，AO 自主实施。

提问时一次性整理已发现的问题，每题使用：

- 需要决定什么；
- 用非技术语言说明对用户的影响；
- 2～4 个互斥选项；
- 推荐项及理由；
- AO 推荐哪项以及不确认会影响什么。

非红色问题由当前操作者确认。红色问题由上级决定；当前操作者转述批准时必须说明批准方案、范围和限制。问题不得只写进文档等人发现；文档只保存聊天确认后的结论。

## 完成时汇报

只汇报五件事：完成结果、主要改动、验证证据、未验证/已知问题、提交或下一步。上级据此验收成果，不审批日常过程。不得用“应该可以”“基本完成”代替证据。
