## 根因（已核对，不是猜测）

- `WebArticleExtractJs` 的 `isBadImg` 用未加边界的 `ads?`。`image-reload` 里的 `ad` 会命中，懒加载 `data-src` 选对之后图仍被丢掉。用旧正则对 `image-lazy image-reload` 测试为命中。
- `isChromeNode` 已有单词边界，同一类名不会被它丢掉。
- 手动「图文混合」走 `openNovelReader(keepImages = true)`，立刻 `evalJs`。自动阅读才有 `delay(700)`。
- `BookHelp` 的 Referer 已优先用章节 URL，但 `ImageProvider.getImageSize` 排版下载时没把章节传进去，邻章会退回打开时的 `customIntro`。

## 实际改动

- `WebArticleExtractJs.imageFilterJs`：`ads?` 改为 `(?:^|[^a-z0-9])ads?(?![a-z0-9])`，并保留 `advert` 前缀；`pagead` / `doubleclick` / `googlesyndication` / `adsbygoogle` 仍拒绝。WebView 脚本与测试共用这段 JS。
- 新增 `WebArticleMixedHydration`：仅 `news.qq.com`、`new.qq.com`、`*.news.qq.com`、`inews.qq.com`、`*.inews.qq.com` 等待。有正文图立刻抽；否则签名连续 2 次不变且已过 700ms，或满 2800ms。
- `BrowserSessionScreen.openNovelReader`：`keepImages` 且上述主机时先等待。文本模式不等待。
- `BrowserWebImageHeaders`：SPEC-092 请求头原样集中。`ImageProvider.getImageSize` / `cacheImage` 增加可选章节，排版传入当前章。

## 真机怎么验

1. 安装包含本次改动的 debug 包（本次未 `assemble`，版本号未进位）。
2. 打开一篇带正文图的网易新闻，长按阅读按钮，选「图文混合」。正文里应看到 `dingyue.ws.126.net` 一类图片，而不是整篇只有字或满屏失败占位。
3. 打开 `news.qq.com`、`new.qq.com` 或 `view.inews.qq.com` 的一篇图文，同样选「图文混合」。提取遮罩会多等一会儿（图一出来就继续，最久约 3 秒），进入后正文图应在。
4. 同一页改选「文本」，正文不应再带这些图。
5. 若图被抽到但加载失败（感叹号），再看图片请求是否带文章 URL 作为 Referer。那是 SPEC-092 的下载头，不是「没抽到」。

## 偏差

- 全量 Gradle 单测因缺少 Aloha AAR 没跑成。计划里的 Node/JVM 断言已补上。
- 刷新已缓存图片的路径（`refreshImageFiles`）仍不传章节，Referer 继续用 `customIntro`。首次排版下载会传章节。
