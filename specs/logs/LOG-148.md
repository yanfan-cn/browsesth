## P5 顶栏与状态栏重叠回归修复（R12）

- **报告**：操作者 10:57 附两张 1.5.2-beta 实机截图——NTP 四键行、书架顶栏与状态栏图标同行重叠。
- **根因**：SPEC-147 R11 将 `AppScaffold` 的 `consumeWindowInsets` 改为无条件消费 `WindowInsets.systemBars.only(Top)`。其「顶栏高度≥状态栏高度 → 子级 inset 补零」等价性只对**有 topBar** 的 scaffold 成立；`MainScreen` 外层包裹（无 topBar、`contentWindowInsets = WindowInsets(0)`）旧实现消费 0，子级依赖剩余状态栏 inset → 全部上移一个状态栏高度。
- **影响面核实**：受影响 = NTP chrome 行（`BrowserNtpScreen` ~504）、平板 chrome（`TabletBrowserChrome` 172/422）、平板设置（`TabletSettingsScreen` 96，`topBar = {}`）。不受影响 = `BrowserHistory/Bookmarks/Tabs`（`windowInsetsPadding(statusBars)` 在 topBar slot，不在 content Box 消费链）、`MainScreen` rail（AppScaffold 兄弟节点）。
- **修复**：`AppScaffold` 加 `topCoveredByScaffold = scaffoldPadding.calculateTopPadding() >= systemBars.asPaddingValues().calculateTopPadding()` 门控：未覆盖时 Top 消费 0（还原旧布局），覆盖时消费 `systemBars.only(Top)`；Horizontal/Bottom 维持 R11。折叠过程 topBar 高度在 ≥ 状态栏区间变化，门控判定不变 → 消费值恒定 → R11 防崩溃（movable content attach 期 `visitSubtreeIf` 上游断言）保持拆除。极端场景（topBar 整体移出组合）门控翻转一次，退化为与旧实现等价的可变消费。
- **验证**：`:app:testAppDebugUnitTest` 全量 0 失败；`assembleAppRelease` 产出 `巡页1.5.3-beta.apk`（待装机确认 AC-6）。
