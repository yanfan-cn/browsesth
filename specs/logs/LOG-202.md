## 实施事实

1. **T1 页眉强制关闭再执行**（`App.kt`）：新增一次性 flag `read_ui_header_off_spec202_v1`，未置位则复用 `applyHeaderHiddenDefault()`（全样式 + 共享排版 headerMode=2、三槽 tipNone），SPEC-112 原 flag 保留。
   - 排查「设置已选隐藏仍显示」：静态核对链路 `TypographyTabs(页眉下拉) → ConfigUpdate.HeaderMode → ReadConfigUpdateDelegate(toReadStyleMutation + updateCurrentStyle) → ReadStyleIntKey.HeaderMode → mutateEffective → configStore.updateEffective(useShare=shareLayout)` 与读取侧 `ReadBookConfig.config = shareLayout ? shareConfig : durConfig` 一致，**未发现静态缺陷**。存疑点：截图（16:10）可能早于操作者的「隐藏」选择；且 HeaderMode 等排版项修改依赖阅读器状态流触发重排，当次会话可能不即时生效。无法在无设备状态下进一步验证，已由 T1 的强制覆盖兜底（下次启动生效）。
2. **T2 杂质清理**（`WebArticleChromeFilter.kt`）：exactLine 增「百度一下，你就知道」；linePatterns 增三条有界正则（`(APP|App|app|应用|客户端)内(打开|查看|阅读)`、`打开(APP|App|app|应用|客户端)`、`(听全文|全文)约?\d+(秒钟?|分钟?)`）。`WebArticleChromeFilterTest` 新增 `filtersBaiduMobileJunkLines`：7 条杂质行命中 + 5 条防误杀断言（含新华社正文两句）。结果：`testAppDebugUnitTest` 7/7 通过（0 failures）。
3. **T3 快捷书签涟漪**（`BrowserNtpScreen.kt` `ShortcutChip`/`AddShortcutChip`）：**与 Plan 偏差一次**——Plan 原方案为 `ripple(bounded=true, shape=...)`，编译发现本项目 material3 `ripple()` 无 `shape` 参数（`No parameter with name 'shape'`），改为等效实现：整格 `combinedClickable(clickable)` 保留（`indication=null`），外层包 `Box`，内容 Column 之外加 `matchParentSize + clip(24dp圆角) + indication(interaction, ripple())` 覆盖层——涟漪仍为 24dp 圆角、覆盖整格，但不再裁切文字（修复「哔哩哔哩」首字被弧线斜切）。
4. **T4 分段控件涟漪**（`BrowserBookmarksScreen.kt` `BookmarksModeSegment`）：同为覆盖层方案（`ripple()` 无 shape 参数），段内容外 `matchParentSize + clip(15dp圆角) + indication` 覆盖层，按压高亮为段胶囊圆角。
