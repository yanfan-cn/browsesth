# LOG-200：长按菜单 4dp 锚定间距（SPEC-200）

> **R2（2026-10-29 上午，操作者反馈后返工）**：操作者指出 R1 理解错了——要求的是「**整个菜单**在底栏/顶栏**之外**、距栏缘 4dp，无重叠」。R1 的 ±4dp 只是锚点槽对齐微调：Above* 语义 = 菜单底边贴**锚点底边**，锚点是栏内小图标槽 → 菜本就压在槽与栏上。R2 重做为按**栏容器窗口边界**定位。

## R2 调查

- Above*/Below* 对齐语义确认（Popup alignment = 在锚点 bounds 内对齐弹出内容）。
- 栏结构：竖屏底栏 = `Row[ Box(weight){FloatingBottomBar(4 项)}, Spacer, 净读 FAB ]`（净读 FAB 在 bar 外、同属底栏 Row，故 provider 必须包整条 Row）；横屏 = 组合顶栏 Row（54dp，含后退/前进/标签槽/净读 FAB）；平板顶栏 = 标签条 40dp + 功能栏 54dp 的整块 Column（两处调用：固定式/动画式）。

## R2 实施

1. `AnimatedMenuPopup.kt`：新增 `MenuPopupBarEdge`（Up/Down）、`LocalMenuBarBounds`、`MenuBarBoundsProvider`（onGloballyPositioned + boundsInWindow）；`AnimatedMenuPopup` 增 `barEdge`/`alignEnd`——有栏边界时走 `PopupPositionProvider.calculatePosition`（菜单底边=栏顶-4dp / 顶边=栏底+4dp，水平贴锚键，含屏内夹边；首帧尺寸 0 由 Popup 测量后自动重定位），栏边界缺失时回退锚点对齐+调用方 offset（NTP 顶栏标签菜单的 belowTopBar 公式经此保留）。
   - 坑①：本工程 Compose 1.13 接口方法名为 `calculatePosition`（非 `getPopupPosition`），且 `geometry.Rect` 为 Float 需转 IntRect。
   - 坑②：竖屏底栏 provider 首次只包了 FloatingBottomBar——净读 FAB 在 bar 外（Row 兄弟节点），会漏锚；已上移包整条 Row。中途用括号配平脚本定位了深层 lambda 闭合行（BrowserSessionScreen 该区域缩进与实际嵌套不一致）。
2. 三个菜单传参：NavHistory（aboveAnchor→Up + alignEnd）、TabCount（aboveAnchor→Up 否则 Down + alignEnd=true）、ReaderMode（belowAnchor→Down 否则 Up + alignEnd=true）。
3. 栏边界布点 4 处：竖屏底栏 Row（BrowserSessionScreen SPEC-169）、横屏顶栏 Row（SPEC-168）、平板两处 chrome Column（TabletBrowserChrome 固定式/动画式）。
