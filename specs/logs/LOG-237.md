## 根因（已实证）

- 操作者真机反馈：导入 Edge 导出文件 `favorites_2026_11_5.html`（125KB，标准 Netscape 格式）后显示「导入失败」。
- 诊断路径（两个临时 JVM 测试，跑完已删）：
  1. 真实文件 `parse` + `importTree`（内存 sink）→ 128 条书签、2 个文件夹，全部导入成功 → **解析层无缺陷**。
  2. 匿名对象作用域最小复现 → `outerCalls=0 stackOverflow=true` → **根因确凿**。
- 根因：`BrowseStore.importSink()` 匿名适配对象内 `override fun addBookmark(...)` 无限定调用 `addBookmark(url, title, folderId)`，Kotlin 名字解析就近命中**匿名对象自身成员**，无限自递归 → 真机导入第一条书签即 `StackOverflowError` → 被 `BrowserBookmarksScreen` 导入按钮处 `runCatching { ... }.getOrNull()` 吞掉 → toast「导入失败」。
- 同对象内 `updateBookmarkToFolder` 用了 `this@BrowseStore.` 限定（正确写法），`addBookmark` 属漏写限定。
- 为什么 SPEC-236 单测没拦住：`BrowserBookmarkHtmlImportTest` 全用测试自备 sink，未触达真实适配层；LOG-236 真机 AC-01/AC-06 当时标注「未验证」。

## 修复

- `BrowseStore.kt` `importSink()`：`addBookmark` 改为 `this@BrowseStore.addBookmark(url, title, folderId)`，并留注释（SPEC-237）。
- 新增回归测试 `BrowseStoreImportSinkTest`（Robolectric，sdk 35）：真实 `BrowseStore` + `importSink()` 落库断言 ×5（addBookmark 落库/文件夹复用/覆盖更新/importTree 端到端/capacityLeft）。测试用例 `importTree` 断言从有序列表改为集合比较（`BrowseStore.addBookmark` 新条目插最前，顺序反转是既有行为）。
- `MAX_BOOKMARKS` 为 private，测试以字面量 1000 锚定并加注释。

## 经验

- 匿名对象覆写方法内调用外层同名方法**必须** `this@Outer.` 限定；同类风险面 = 所有 `*Sink`/回调适配对象。后续 review 可 grep `override fun` + 同名无限定调用。
