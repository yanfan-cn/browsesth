# LOG-151 净读模式 release 提取失败修复

关联：SPEC-151、PLAN-151。日期：2026-10-20。状态：已实施，验证通过，AC-1/2 待装机复核。

## 复现确认（操作者报告）

- 「近两个版本（1.5.3/1.5.4）净读模式不可用，点击即显示：未能提取正文，请换一个页面再试」，指令参照前面版本修复。

## 根因（关键证据）

1. 提取管线代码（`WebArticleExtractJs`/`WebArticleChromeFilter`/`parseExtractResult`）自 1.3.8 提交（`8c62580`）后未变；「未能提取正文」唯一出处是 `openNovelReader` 的 `cleaned.length < 40`。
2. 版本装机形态：1.5.2 及以前为 **debug 包**（`isMinifyEnabled=false`）；1.5.3 起（SPEC-148）改发 **release 包**（`isMinifyEnabled=true`，R8）——两版本间唯一实质运行时差异。
3. WebView JS 结果中由 **GSON 反射按字段名**解析的 4 个私有 DTO 均无 `@SerializedName`、无 keep 规则：R8 重命名字段 → JSON 键 `title/html/text/cover` 等失配 → 解析全 null → 正文长度 < 40 → 弹「未能提取正文」。手写 `JsonParser` 按键取值的路径（`parseToc`/`parseExpand`/`parseProbe`）不受影响，与现象吻合。

## 实施

1. **@SerializedName 显式注解（主修复）**：
   - `WebArticleBookFactory.ExtractDto`（title/html/text/cover）
   - `WebMangaBookFactory.AnalyzeDto`（kind/title/textLen/imgCount）
   - `WebPageLangDetect.Dto`（lang/sample）
   - `BrowserContextMenuPayload`（href/text/img/title/page，`ui/browser/BrowserLinkContextMenu.kt`）
2. **proguard 兜底**（`proguard-rules.pro` 末尾）：`-keepclassmembernames` 保 `io.legado.app.browser.reader.**` 与 `BrowserContextMenuPayload` 的字段名，覆盖后续新增同类 DTO。
3. 未改提取脚本、过滤、宿主回退逻辑；未回退 R8。
