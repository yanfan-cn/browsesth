## 真机问题 #1（2026-10-19 10:23）：手势返回被底层会话劫持

- **症状**：网页中打开历史/收藏/标签页后，**系统手势返回**卡很久、最终落到浏览器主页；页面内左上角返回键正常（回网页）。
- **根因**：`BrowserSessionScreen` 的 `BackHandler(enabled = true)`（L1052）。SPEC-139 前 Home 被 overlay 覆盖时**不组合**、该 handler 不存在；SPEC-139 后 Home 常驻组合且 handler 注册晚于 NavDisplay 的 back 处理 → **优先级更高**，手势返回被劫持：先不可见地 `webView.goBack()`（「卡很久」），页内历史耗尽后走 `onNavigateBack()` = `clearActiveToNtp()` → 落到主页。返回键走回调不经 dispatcher，故不受影响。
- **修复**：nav3 把被 overlay 覆盖的底层场景 lifecycle 压到 `STARTED`（NavDisplay.kt L830-836，overlay 移除时才回 `RESUMED`）→ 会话 BackHandler 改为 `enabled = lifecycleState.isAtLeast(RESUMED)`（`LocalLifecycleOwner.current.lifecycle.currentStateAsState()`）。被覆盖时禁用、露出时恢复；无 overlay 时的手势返回行为与 SPEC-139 前一致。
- 其余 BackHandler 排查：视频播放器=独立 Activity；Activity 级 handler 注册最早（优先级最低）；`MainScreen` 仅书架页启用；平板 `TabletBrowserChrome` 两处仅在壳内侧栏/菜单打开时启用且平板不 push 这些路由 → 均不受影响，只改会话一处。
