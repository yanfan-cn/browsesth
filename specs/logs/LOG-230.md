# LOG-230

## TC-01 真机实测（2026-11-04，设备 3471820292003U8，com.browsesth.app）

`run-as` du 统计（单位 KB），总计 ~957 MB：

- `cache/`（系统设置“缓存”主体）≈ 377 MB：
  - `cache/WebView/Default/HTTP Cache` 220 MB（Cache_Data 147 MB + js Code Cache 72 MB）——内核 HTTP 缓存就在 cacheDir 下
  - `cache/http_cache` 106 MB（OkHttp 封面缓存，贴近 100 MB 上限）
  - `cache/WebView/Crashpad/pending` 36 MB（崩溃转储积压）
  - `cache/manga_previews` 13 MB；`oat_primary` 1.5 MB
- `app_br_webview/` 569 MB（被部分 ROM 计入缓存口径）：
  - **`BrowserMetrics` 533 MB**——Chromium 本地指标日志，无淘汰机制，纯垃圾增长
  - `adblock_subscriptions` 17 MB；IndexedDB/Service Worker/Local Storage 等站点数据 ~8 MB（不自动清）
- `externalCache/` 仅 crash/logs 几十 KB；exoplayer 播放缓存本次为空（上限 100 MB LRU）
- 发现旧缺陷（未修，边界外）：`BrowserClearDataHelper.clearCacheDirs` 清的是 `app_bromium`，真机实际目录名是 `app_br_webview`，该目录从未被「清除浏览数据」清过——这正是 800 MB 缓存的构成（220 MB 网页缓存 + 533 MB 指标）。

## 实施事实

- 2026-11-04，分支 main，工作区含大量未提交改动（保留不动）。
- 合并变更（操作者 2026-11-04 确认）：
  - `DownloadCacheConfigContract/ViewModel/Screen` 重构：删除「HTTP缓存」组两条目（由统一六分类取代）、「图片缓存」组、「网络」组（UA/Cronet）、「高级」组（清理缓存 + 压缩数据库，均为操作者明确选择删除）；相关 Intent（SetBitmapCacheSize/SetImageRetainNum/SetUserAgent/SetCronetEnabled/ShowDialog/DismissDialog/ConfirmDialog）、Dialog 枚举与 UseCase 依赖移除；「下载」组滑块保留。
  - 新增「缓存清理」组（六分类实时大小 + 点击清理）、「自动清理」组（开关 + 上限切换）、「一键清理全部缓存」按钮；`StorageCacheViewModel` 由 `DownloadCacheConfigRouteScreen` 注入并收集 Toast 效果，进入页面时自动 Refresh。
  - 删除独立 `StorageCacheScreen.kt`、路由 `MainRouteBrowserStorageCache`、`SettingsActivity` entry、`BrowserConfigScreen`/`TabletSettingsScreen` 的入口与传参；`StorageCacheStats`/`StorageCacheAutoTrim`/`StorageCacheViewModel`/单测保留。
  - `ClearBookCacheUseCase`/`ShrinkDatabaseUseCase` DI 注册保留（书籍信息页/书架管理等处仍在使用），仅本页入口移除。
  - 已删除组的字符串资源（http_cache/cover_cache/network/other_setting 等）暂保留未删，避免跨语言资源联动改动。
