## 手机为什么没变化

中午包 `巡页1.2.5-beta.apk` 来自本机脏 `main`（`version.properties` 已到 1.2.6）。那棵树上的 `WebArticleExtractJs.kt` 仍是未加边界的 `ads?`。本分支当时是草稿 PR，没有进 GitHub `main`。本机 `git fetch` 失败，所以手机里的包不可能含这次修复。

## 根因

- `isBadImg` 未加边界的 `ads?` 命中 `image-reload`。`data-src` 选对之后图仍被丢掉。Node：旧正则对 `image-lazy image-reload` 为命中，新边界正则为不命中。`upload/read` 同样不再被当成广告。`isChromeNode` 仍是 `\bads?\b`，不会单独丢掉该 img。
- 手动「图文混合」立刻 `evalJs`。自动阅读才有 `delay(700)`。腾讯首页壳 `xw.qq.com`（2026-10-16）是 Next.js，页面里 `<img` 为 0。
- 排版下载原先不把章节传进 `saveImage`。当前章的 `customIntro` 仍可作 Referer；邻章会错。
- 2026-10-16 用手机 UA 打开 `https://www.163.com/dy/article/L99ASMRC0512D3VJ.html`，落到 `https://m.163.com/dy/article/L99ASMRC0512D3VJ.html`。正文两张图类名 `image-lazy image-reload`，`src` 是 `empty.png`，`data-src` 是 `http://dingyue.ws.126.net/…jpg`。同一 URL：带该文 Referer 得到 `200 image/jpeg`（138205 字节）；不带 Referer 得到 `302`，最终是 `data:image/png;base64,…` 而不是照片。桌面同一篇没有 `image-reload`，图片已是 `https://nimg.ws.126.net/?url=…`。

## 实际改动

- `WebArticleExtractJs.imageFilterJs`：`ads?` 改为 `(?:^|[^a-z0-9])ads?(?![a-z0-9])`，保留 `advert` 前缀；`pagead` / `doubleclick` / `googlesyndication` / `adsbygoogle` 仍按子串拒绝。`abs()` 先把 `//` 补成 `https:`。
- `WebArticleMixedHydration`：仅 `news.qq.com`、`new.qq.com`、`*.news.qq.com`、`inews.qq.com`、`*.inews.qq.com` 等待。有正文图立刻抽；否则签名连续 2 次不变且已过 700ms，或满 2800ms。
- `BrowserSessionScreen.openNovelReader`：`keepImages` 且上述主机时先等待。文本模式不等待。
- `BrowserWebImageHeaders`：`Accept` 改为 `image/jpeg,image/png,image/webp,image/*;q=0.8`。章节 http(s) URL 优先作 Referer。
- `ImageProvider.getImageSize` / `cacheImage` 增加可选章节，排版传入当前章。
- `WebChapterHttpFetcher.preferredImgSrc`：懒加载属性优先于 `data:` 占位，`//` 补 `https:`。
- logcat 标签 `BrowsesthReader`：`wait hydration host=`、`extract keepImages= imgs= host=`、`image fail host= `（异常类名或 `decode-null`）。不打完整 URL。
- 规格编号改为 SPEC-127。本分支删除误占的 SPEC-123 / PLAN-123 / LOG-123。补丁不含交接文档、SPEC-092、SPEC-109，也不含 SPEC-123，避免盖住本机那份页面抖动规格。

## 本机怎么装上（不能 git fetch 时）

1. 用浏览器打开并保存补丁（git 的 HTTPS 代理失败时，浏览器有时仍能下）：
   `https://github.com/yanfan-cn/browsesth/raw/cursor/mixed-reader-news-images-0adc/specs/logs/SPEC-127-apply-on-local-main.patch`
2. 在 `D:\cursor\browsesth`：
   `git apply --reject --whitespace=nowarn <补丁路径>`
3. 补丁只改抽取、等待、图片请求、对应测试和 SPEC-127 三件套。不改 `docs/会话状态交接.md`，不改 SPEC-092 / SPEC-109，不写 SPEC-123。若 `BrowserSessionScreen.kt` 或 `BookHelp.kt` 因本地改动出现 `.rej`，先看 `WebArticleExtractJs.kt` 是否已加上边界正则；那一行不去，图文混合仍会丢掉 `image-reload`。
4. 设 `$env:GRADLE_USER_HOME="D:\cursor\.gradle-home"` 后再 `assemble*`。装新包。旧的 `巡页1.2.5-beta` 不含此修复。

GitHub 上合并：PR #1，分支 `cursor/mixed-reader-news-images-0adc` → `main`。合并不会带上 SPEC-123。本机在能 fetch 之前，用上面的补丁，不要用合并 GitHub `main` 来覆盖本地未提交工作。

## 真机怎么验

1. 安装打过本补丁之后的新包。`adb logcat -s BrowsesthReader:I`。若全程没有 `BrowsesthReader`，装上的仍是旧包。
2. 长按阅读按钮（书图标）选「图文混合」，不要选「文本模式」。短按在正文够长时也是图文混合。「图片模式」是漫画阅读器。
3. 网易手机正文（`m.163.com`，类名 `image-lazy image-reload`）：应出现 `extract keepImages=true imgs=` 且数量大于 0，随后正文图可见。`keepImages=false` 表示走了文本模式。
4. 腾讯 `news.qq.com` / `new.qq.com` / `view.inews.qq.com`：先有 `wait hydration host=`，再有抽取行。图一出来就继续，最久约 3 秒。
5. 若 `imgs` 大于 0 但屏幕仍无图：看 `image fail host=dingyue.ws.126.net`。`decode-null` 多半是没带上文章 Referer（CDN 回了假图）或解码失败。那是下载，不是抽取。
6. 同一页改选「文本模式」：`imgs=0`，正文不应再带这些图。

## 偏差

- 全量 Gradle 单测因缺少 Aloha AAR 没跑。
- `refreshImageFiles` 仍不传章节，Referer 继续用 `customIntro`。首次排版会传章节。
- 没有把 WebView Cookie 同步进 OkHttp。这次拉取的网易图只要求 Referer，不要求 Cookie。
- 用户替换规则若按行删掉 `<img>`，仍会没图。未改。
