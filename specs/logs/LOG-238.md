## 诊断过程（adb 实测，平板 2032x3048）

1. **「书签打不开」先排除了收藏页**：uiautomator dump 定位侧栏书签行 → input tap → 面板收起、当前标签成功加载目标页（后续复测确认链路通）。API2D 打不开为站点自身问题（操作者确认），非 bug。
2. 操作者澄清后转向**书签页（阅读书签）**：点击后无 toast、无跳转、栈顶不变 → 复现。根因：`TabletBrowserChrome` 侧栏 `BrowserBookmarksScreen(onBack, onOpenUrl)` 两参调用，`onOpenBook` 落默认空 lambda——阅读书签路径 `openEntry → openReadingBookmark → onOpenBook(book)` 直接空操作。
3. **顶栏空白**：截图（裁剪）确认侧栏顶栏行上方约 100px 空白带；`BookmarksModeTopBar`/`BrowserHistoryScreen` 顶栏硬编码 `windowInsetsPadding(WindowInsets.statusBars)`，侧栏已在浏览器 chrome 下方，重复吃 inset。旁证：Downloads 侧栏无 statusBars padding、无此问题。

## 实施事实

1. **修复 A（顶栏空白）**：`BrowserBookmarksScreen`/`BookmarksModeTopBar`、`BrowserHistoryScreen`/`BrowserHistoryBody` 各加 `inSidePanel: Boolean = false`；顶栏 statusBars 避让改为条件应用（侧栏不再吃）。平板侧栏两调用点传 `inSidePanel = true`。
2. **修复 B（阅读书签）**：
   - `TabletBrowserShell` 加 `onOpenBook: (Book) -> Unit = {}`；侧栏 `BrowserBookmarksScreen` 传 `onOpenBook = { onOpenBook(it); 收起侧栏 }`。
   - `BrowserHomeTabScreen`（外壳+Body）加 `onOpenReadingBookmark: (Book) -> Unit = {}`（与既有 onOpenBook→书籍详情语义区分），shell 调用 `onOpenBook = onOpenReadingBookmark`。
   - `MainScreen`：`onOpenReadingBookmark = { context.startActivityForBook(it) }`——书签章节位置已在 `openReadingBookmark` 写入 book.durChapterIndex/pos；音频/漫画/文本路由由 util 按 `MangaSettingsGateway.showMangaUi` 决定。
3. 手机端（MainNavGraph 接线、全屏页面 statusBars 避让）零改动。

## 偏差与备注

- `startActivityForBook` 不带 `inBookshelf = !book.isNotShelf`（MainNavGraph 版本有）：阅读书签必然产生自阅读中的书，`isNotShelf=false` → 两者结果一致；如后续出现非书架书签场景再补。
- adb 实测时发现侧栏书签点击后 `touchBookmarkOpened` 会触发列表重排（`lastOpened` 参与排序），导致连续实验中行位置漂移——非 bug，记录备查。
