# LOG-153 release 包两大严重 bug 修复

关联：SPEC-153、PLAN-153。日期：2026-10-21。状态：已实施，编译+单测+构建+签名通过，AC-1/AC-2 待装机复核。

## 根因取证（要点，详见 SPEC-153）

1. **长按闪退**：Bromium（捆绑 Chromium）不用编译期 R 常量，启动时 `BromiumResources` 读 `res/xml/bromium_res_index.xml` 做全量「名字→ID」映射（缺索引再逐名 `getIdentifier` 兜底）。release 的资源压缩（`isShrinkResources=true`）静态分析无法追踪这些按名解析，删了索引本体 + `aw_context_menu_*` / `text_edit_suggestion_*` 等 1300+ 项（对比 debug 1567 项 vs release 875 项）。长按是首个触发 Chromium UI 资源加载的路径 → `Resources$NotFoundException` → 闪退。1.5.2 及以前装机为 debug 包（无压缩）故不复现。
2. **网页背景失效**：`applyWebContentDarkMode` 等以字符串反射调 Bromium `AwSettings` 的 public 方法；R8 mapping 证实 `AwSettings` 类名保留但成员被改名/移除（`setForceDarkMode` 在 mapping 与 APK dex 字符串池中消失），`getMethod` 抛 `NoSuchMethodException` 被 `runCatching` 静默吞掉 → 设置永不生效。同批静默失效：`setImagesEnabled`/`setLoadsImagesAutomatically`/`setCacheMode`/`setAllowFileAccess`/`setAllowContentAccess`/`setSafeBrowsingEnabled`。
3. 两 bug 均为 SPEC-148 起 release 组装（R8+资源压缩）引入，与操作者「切 release 后出现各种严重 bug」的判断一致；SPEC-151 的 GSON/DTO 属同类根因家族。

## 实施

1. **R1** `app/build.gradle.kts`：release `isShrinkResources = false`（保留 `isMinifyEnabled = true`；debug/noR8 不动），注释注明 Bromium 运行时按名解析与压缩器不兼容的原因。
2. **R2** 反射改直调（均保留 runCatching 容错与失败日志）：
   - `AwContentsHostView.attach`：`setImagesEnabled(true)`、`setLoadsImagesAutomatically(true)`、`cacheMode = -1`、`setAllowFileAccess(true)`、`setAllowContentAccess(true)`；
   - `AwContentsHostView` companion `applyWebContentDarkMode`：`setForceDarkMode(forceMode)`、`setForceDarkBehavior(2)`、`setAlgorithmicDarkeningAllowed(true)`；
   - `BrowserPrivacyControls.applyToSettings`：`setSafeBrowsingEnabled(...)`；
   - `applyForceZoom` 两处反射（javap 核实 SDK 无 `setForceEnableZoom`/`setForceUserScalable`）维持现状，JS 视口兜底仍在。
3. **R3** `proguard-rules.pro`：追加 AwSettings 反射目标成员的 `-keepclassmembers` 兜底规则（注释注明 SPEC-153）。

## 版本与偏差

- **首次 assemble 出现「双 bump」**：`org.gradle.configuration-cache=true` 且 bump 在配置期写 `version.properties`，一次 assemble 配置阶段跑了两次（199/1.5.7 → 误产 `巡页1.5.8-beta` code 200，props 落 1.5.9/201）。已按交接规则处置：删除错号产物、props 回写 **1.5.7/199**、以 `--no-configuration-cache` 重打 → 本包 **`巡页1.5.7-beta`（code 199）**，props 单次进位 **1.5.8/200**。
- **遗留风险（已向操作者披露，未在本 SPEC 处理）**：configuration cache 开启时 bump-on-configure 可能再次双 bump 或（cache 命中时）漏 bump；建议后续把 bump 移到 task 执行期或 assemble 时固定 `--no-configuration-cache`。
- 其余无偏差；未 commit/push（未获指示）。
