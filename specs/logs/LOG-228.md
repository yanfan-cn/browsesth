## 2.3.0 装机后仍无效 → adb 实锤两处根因

1. **AVIF**：拉取设备缓存 `视频丨科技融设计…/images/a5396fc01f9d9932.jpg`，文件头 `ftyp avif`。
   `BrowserWebImageHeaders` 的 Accept 头写着 `image/avif,...`，腾讯 CDN 按 Accept 真给 AVIF，
   而本机 HEIF 栈不支持（logcat 反复 `HeifDecoderImpl: getSize: not supported`）→ 图永远空白。
2. **建书中断**：`unknown protocol: browsesth-jingshi` @ `WebArticleBookFactory.normalizeMixedHtml`
   ——占位/待定 src 传进 `HtmlFormatter.formatKeepImg`（内部 `java.net.URL` 解相对路径）直接抛异常，
   createEphemeralBook 中断 → 净读视频位空白与「无改善」的直接原因。

## 追加修复（2.3.1）

1. `BrowserWebImageHeaders`：Accept 改 `image/webp,image/jpeg,image/png,image/*;q=0.8,*/*;q=0.8`（不再广告 avif）。
2. `BookHelp.checkImage`：新增 `isAvifFile`（ftyp avif 魔数）→ 判无效，触发重下。
3. `ImageProvider.cacheImage`：已存在但 `isImageValid=false` 的 http 图视为缺失 → 就地重下（自愈旧 AVIF 缓存）。
4. `ImageProvider.getImageSize`：`browsesth-jingshi://` 伪协议直接回 16:9 尺寸（800×450），不再联网下载占位；
   全解失败时删除坏缓存文件再回 Size(0,0)。
5. `WebArticleBookFactory.normalizeMixedHtml`：格式化前把 `browsesth-jingshi://` 掩码成
   `https://jingshi.browsesth.invalid/`，完毕后还原；format 异常兜底返回原文。
6. 单测：`normalizeMixedHtmlKeepsJingshiPseudoScheme`、`sanitizeDropsArticlePageImgKeepRealImages`、
   `BrowserWebImageHeadersTest` Accept 断言更新。全绿。
7. `assembleAlohaDebug` → **2.3.1-beta** 装机；装机前 adb 清掉「视频丨科技融设计…」「超火的图文带货滚动…」两本陈旧书缓存。

## 2.3.1 装机后仍无效 → 录屏 + 逐帧分析实锤第三处根因（视频位黑块真因）

用户实际测的是「视频丨一次送18颗卫星！」一文。录屏显示视频位是**纯黑块**（暗色主题背景透出），
正文图可显示。该书缓存 4 个文件全部为可解码 WebP，logcat 无任何解码/下载错误。

**根因（SPEC-212 起一直存在）**：图片缓存 key 错位——
- 排版 `LegacyReaderChapterPaginator` → `ImageProvider.getImageSize(book, src带#browsesth-jingshi)`
  → `BookHelp.getImage` 文件名 = `MD5(带片段src).jpg`（已实测：`417199be6dcf05e3` = MD5(带片段)）
- 显示 `ReadBookController.loadReaderImage` 把片段剥掉再查 → `MD5(不带片段)` 的文件**不存在**
  → errorBitmap → 「缺图不画」→ 黑块
- 普通 gtimg 图无片段、两侧 key 一致 → 所以只有海报位黑、正文图正常。

**修复（2.3.2）**：`loadReaderImage` 直接用带片段的原 `element.source` 查缓存（位图与片段无关），
排版/显示两侧 key 对齐。无需清缓存（带片段的缓存文件本就存在）。
`assembleAlohaDebug` → **2.3.2-beta** 装机。
